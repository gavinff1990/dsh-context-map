## What it is for

At the end of a long session the useful part is buried: why the direction changed, which file is the deliverable, what is still undecided. Scrolling back does not recover it, and screenshots are not structure.

`dsh-context-map` has the agent distill that conversation into a **semantic tree**, then renders it:

- **Layered left-to-right**, not a radial mind map: depth is a column, so the structure reads in one pass.
- **Seven fixed kinds** — goal, context, decision, action, artifact, risk, open question — with a stable color per kind.
- **Three artifacts**, each with a job: `svg` for documents, `html` for zoom/search/filter/print, `md` for a reviewable diff with Mermaid source.
- **Deterministic**: the same input always produces the same coordinates, so a committed map does not churn on every regeneration.

## Install

```sh
dsh plugin --profile web add dsh-context-map

# from a checkout
dsh plugin --profile web add /absolute/path/to/dsh-context-map
```

Desktop profiles are managed by the application — install from the in-app plugin market, or add this row to `~/.dsh/profiles/desktop/cordis.patch.yml`:

```yaml
- id: context-map
  name: dsh-context-map
```

No configuration, no API key, no network call.

## Use

Say something like:

> Map the context of this discussion.
> Draw an architecture map of this project, with risks and open questions.

The agent calls `context_map` and returns three paths:

```
.dsh-context-map/context-map.svg
.dsh-context-map/context-map.html
.dsh-context-map/context-map.md
```

Prefer an **absolute** `outDir` when you care where the files land: the plugin process working directory is not necessarily the session workspace.

### Parameters

| Parameter | Required | Meaning |
| --- | --- | --- |
| `title` | ✅ | Map title, one line |
| `nodes` | ✅ | `{ label, kind?, detail?, parent?, id?, status? }` |
| `subtitle` | | The question this map answers |
| `links` | | Cross-branch dependencies the tree cannot express |
| `outDir` | | Output directory, default `.dsh-context-map` |
| `slug` | | File base name, derived from the title by default |
| `formats` | | Subset of `svg`, `html`, `md` |
| `theme` | | `light`, `dark`, `auto` |
| `locale` | | `zh`, `en` |

### Kinds

| kind | Meaning |
| --- | --- |
| `goal` | What the user actually wants |
| `context` | Constraints, established facts, external rules |
| `decision` | A choice already made |
| `action` | Work in progress or planned |
| `artifact` | A file, repository, document or diagram |
| `risk` | Something that can break the plan |
| `question` | Still open |
| `note` | Worth keeping, none of the above |

`status` (`done` / `active` / `planned` / `blocked`) is drawn as a dot.

## Design notes

- **Zero runtime dependencies.** The tool registers a raw `ToolDefinition`, so `parameters` is already the wire-level JSON Schema — nothing to drift when the authoring DSL changes.
- **No model call.** Distillation belongs to the agent, which already holds the conversation. The plugin stays a pure function: testable, reproducible, free.
- **Computed layout.** Column widths from the widest card, parents centered on their children's subtree band, deterministic stacking. See [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).
- **One SVG, two themes**, via CSS variables and `prefers-color-scheme`; the HTML export can also toggle manually and prints to A3 landscape.

## Privacy

No network. No session-log access. Writes exactly three files under `outDir`, and refuses the filesystem root, `~/.dsh`, `~/.ssh`, `~/.aws` and similar locations. No subprocess, no eval.

## Compatibility

DSH `>=0.2.0-rc.1 <0.3.0-0` · Node `>=20` · macOS, Linux, Windows.
